# 功能清单（Function Tree）— SaaS 身份平台 Go 端

> **全体系唯一锚点。** 需求、流程、设计、测试都引用这里的 ID。
> 不在这里的 ID 是悬空引用，L5 门会拦。**改功能，先改这份表。**

## 编号规则

| 层级 | 名称 | 格式 | 含义 |
|---|---|---|---|
| 一级 | 功能模块 | `M01` | 业务域边界，通常对应一级菜单 |
| 二级 | 功能 | `M01.F01` | 一个完整业务步骤 / 独立闭环流程 / 数据管理页面 |
| 三级 | 功能子项 | `M0x.F0y.I0z` | 技术交付单元 / 权限挂载点。对应一个 API 接口、页面组件、图表区块或权限控制点 |

**硬规则**

1. 编号单调递增，永不复用。废弃改状态，不删行。
2. 子项编号必须以父级为前缀。
3. 一个子项 = 一个权限点。权限码即 ID，不另起一套编码。
4. 拆不出子项的功能 → 它其实是子项，往上并。子项超 20 个 → 它其实是模块，往下拆。

**状态**：`规划` | `开发中` | `已上线` | `已废弃`
**子项类型**：`页面` | `标签页` | `查询` | `按钮` | `报表` | `接口`
**交付**：`前端+后端` | `仅前端` | `仅后端`

## 本仓角色

**契约消费仓**（BASE=`saas-identity-platform-shared`，spec §3）。F 级镜像照抄 BASE（ADR-0024 消费仓照抄 BASE）；I 级为全家族定标源，**本仓暂未登记任何 I 级**——首个需求来了，按 BASE 对应 F 段的 I 级走 mirror 登记（`python scripts/tree_change.py -p saas-identity-platform-go --apply`，提案 `mirror: true` 免批）。

范围：M00 租户管理 / M01 用户管理 / M04 应用管理（2026-09-07 新结构）。
多租户：tenant 跨切是平台默认语义；租户真相源在 BASE 仓。
M97/M98/M99/M96（infra / 契约专属段）不进 BASE，由本仓自管。

**状态口径**：消费仓状态 = 本仓那半边交付了没有。本仓零代码，全部落「规划」；
随切片交付走 mirror 登记翻状态，不体感抄 BASE。

## 维护约定

- 谁改功能，谁改表，同一个 commit。
- **改树走 `/tree-change` 提案**：mirror 登记 / 规划→开发中 / 开发中→已上线 走
  `--apply` 免批；废弃与 BASE 仓改动仍人工 `--approve`。
- `规划` → `开发中`：必须先有需求文档引用它。
- `开发中` → `已上线`：GA 前先把「人工验收 …通过」写进 REQ 文档（GA_ACCEPT_RE 过检）。
- I 级子项拆分：从 BASE 对应 F 段照抄 ID/名称/交付，类型按本仓栈自标（Go 端 = 接口/查询）。
